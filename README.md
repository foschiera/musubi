# Musubi

Musubi explores history as a graph of connected events, with sources and narratives from different regional perspectives and languages. It supports filtering historical connections and finding paths between events.

The runnable prototype includes a C++20 HTTP API, an in-memory graph engine, an interactive TypeScript/D3.js atlas, and a curated JSON demo dataset. Explore the graph or event list, filter your research lens, compare multilingual summaries, and find sourced connections between events.

## Run the app

With Node.js 20.19+ (or 22+), npm, GNU Make, Python 3 and a C++20 compiler installed:

```bash
make setup
make run
```

Open **http://127.0.0.1:8080**. `make run` builds both components and serves the app and API from the same process. Fonts and frontend assets are bundled locally; the running app needs no network access. Source links open external sites when selected.

## Run the API

You need GNU Make and a C++20 compiler such as `g++`. The C++ dependencies, cpp-httplib and nlohmann/json, are vendored in this repository. No database or API keys are required.

From the project root:

```bash
make build/musubi
make validate-data
./build/musubi
```

The server listens at `http://127.0.0.1:8080`. In another terminal, check it with:

```bash
curl http://127.0.0.1:8080/health
curl http://127.0.0.1:8080/api/v1/graph
```

Keep the project root as the working directory: dataset and static asset paths are relative to it. The server serves frontend assets from `dist/`, generated by `make build`.

## API usage

| Method | Endpoint | Purpose |
| --- | --- | --- |
| GET | `/health` | Server health and dataset version |
| GET | `/api/v1/meta` | Taxonomies, sources, and editorial note |
| GET | `/api/v1/graph` | Filtered nodes and relationships |
| GET | `/api/v1/events` | Event list with cursor pagination |
| GET | `/api/v1/events/{id}` | Event narratives and resolved sources |
| POST | `/api/v1/paths` | Find a path between two events |

Graph and event-list queries support `region`, `perspective`, `relationship_type`, `from`, `to`, `q`, and `limit`. Taxonomy filters accept comma-separated IDs; use `/api/v1/meta` to discover them. The event list also accepts `cursor` from the preceding response's `next_cursor`.

```bash
curl 'http://127.0.0.1:8080/api/v1/graph?region=south_asia&from=1940&to=1960'
curl 'http://127.0.0.1:8080/api/v1/events/evt_bandung?language=pt-BR'

curl -X POST http://127.0.0.1:8080/api/v1/paths \
  -H 'Content-Type: application/json' \
  -d '{"from_event_id":"evt_india","to_event_id":"evt_bandung","strategy":"fewest_hops"}'
```

Path searches respect relationship direction and support two strategies:

- `fewest_hops`: minimize the number of relationships traversed.
- `highest_confidence`: minimize the sum of `6 - confidence` across relationships, where confidence ranges from 1 to 5.

Optional path `filters` use `region_ids`, `perspective_ids`, and `relationship_types` arrays, alongside `from`, `to`, `q`, and `limit`.

## Configuration and data

| Environment variable | Default | Purpose |
| --- | --- | --- |
| `MUSUBI_HOST` | `127.0.0.1` | Listening address |
| `MUSUBI_PORT` | `8080` | Listening port |
| `MUSUBI_DATASET_DIR` | `data/demo` | Dataset directory |

For example:

```bash
MUSUBI_PORT=8090 MUSUBI_DATASET_DIR=data/demo ./build/musubi
```

Each dataset directory contains `dataset_manifest.json`, `events.json`, `relationships.json`, `sources.json`, and `taxonomies.json`. Data is validated and loaded into memory at startup; restart the server after editing it. To validate another dataset without starting the server:

```bash
make validate-data DATASET=path/to/dataset
```

The demo, **Threads of independence**, contains 8 events and 9 relationships. Its summaries and connections are editorial prototype material, not quotations or claims of scholarly consensus. Region tags represent the research lens; event locations are recorded separately.

## Development status

The frontend tooling uses Node.js, npm, TypeScript, Vite, and D3.js. `make setup` installs the locked npm dependencies. `npm run dev` starts Vite with `/api` and `/health` proxied to the backend at `127.0.0.1:8080`; run the API separately.

Available checks:

| Command | Behavior |
| --- | --- |
| `make build` | Build the backend and type-check/bundle the frontend |
| `make run` | Build both components and start the server |
| `make test` | Run graph unit tests and API integration tests on port 18081 |
| `make validate-data` | Check JSON Schemas, UTF-8/NFC and cross-file references |
| `npm run test:browser` | Exercise desktop/mobile flows with the app running on port 8080 |
| `make check` | Build, validate data, test, and verify frontend/data formatting |

The browser test uses `/usr/bin/google-chrome` by default; set `CHROME_BIN` to another Chromium-compatible executable. It writes screenshots and an accessibility report to ignored `test-results/`. CI runs `make check`; browser verification is a separate local check.

## Try these journeys

The atlas now uses a dark, force-directed graph inspired by [Obsidian’s graph view](https://obsidian.md/help/plugins/graph). Node size reflects connection count; hovering highlights immediate neighbors.

- Scroll/pinch or use **+ / −** to zoom between an overview, labeled events, and detailed event summaries. Below 70% labels fade; at 220% the selected event’s detail card appears.
- Double-click a node, press **F** while it has keyboard focus, or choose **Zoom into this event** to center it and reveal its summary, narrative count, and source count. **Read perspectives & sources** opens the reading panel.
- **Focus event** emphasizes a one- or two-hop neighborhood. Other events remain dimmed for context, so the API and route finder continue to use the same filtered graph. **All events** or **Back to the wider graph** restores the previous camera.
- Drag nodes to pin their positions. Open **Graph settings** to adjust repulsion and link distance, toggle labels/arrows, or reset the layout and clear pins.
- With the graph focused, arrow keys pan, **+ / −** zoom, **Enter** selects, and **Escape** leaves event focus. The List view remains available on small screens and for keyboard navigation.

1. Select **The Bandung Conference** and read its English, French, Japanese and Portuguese summaries. Open a source to examine the underlying reference.
2. Select **Africa** in the region filter, switch to **List**, and copy the view link. Reloading restores the filters and selection.
3. Choose **Find a connection**, from **The Bandung Conference** to **The Global South finds a voice**. Inspect the two-step route and its source links; switch to the confidence-weighted strategy to compare it.

## Prototype boundaries

This implements the main M0–M3 exploration journeys, with a small eight-event collection. It is not a completed M4 release. Search currently folds ASCII case only; region hierarchy expansion, full interface translation, benchmark budgets, full OpenAPI contract validation, structured request metrics, sanitizer CI, and automated hot reload of datasets remain future work. The graph uses curated coordinates as seeds for a force simulation. Schemas currently require the prototype's `layout` and `location` extensions. Camera positions, pins and force settings last for the current page session; filters and selected event are shareable by URL.

Run `make validate-data` before serving an edited dataset: startup performs semantic validation, while the offline command additionally checks the schemas and NFC normalization. Normalization is checked rather than silently rewriting a curator’s content. Confidence values on tentative editorial links are demonstration scores, not externally validated measures. The region selector includes selected regions; exclusions are expressed by selecting the complementary regions.
